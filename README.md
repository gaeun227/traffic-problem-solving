# 교통문제 해결 데이터 분석 공모전 — 작업 하네스

이 저장소는 주제를 확정하기 전 두 후보의 **데이터 확보 가능성, 분석 완성 가능성, 정책 효과 검증 가능성**을 비교하는 작업 공간이다. 아이디어의 매력과 실제로 입증한 결과를 구분한다.

## 먼저 읽을 문서

1. [공모전 요구사항](docs/contest.md): 마감·제출 형식·심사 방향
2. [주제 선택 기준](docs/decision.md): 두 후보를 같은 기준으로 검증하는 방법
3. [새벽 이동 단절](ideas/01-early-bird.md) / [혼잡 추가배출](ideas/02-congestion-carbon.md): 각 주제의 질문과 첫 검증 과제
4. [근거 기록법](research/README.md): 확인한 자료와 미확인 주장을 기록하는 방식

## 운영 순서

1. **자료 확인**: 원자료의 주소, 제공기관, 이용조건, 시간·공간 단위를 기록한다.
2. **작은 표본으로 연결 실험**: 전체 서울·수도권을 처리하기 전에 1개 지역·짧은 기간으로 핵심 결합이 되는지 확인한다.
3. **두 주제 비교**: `docs/decision.md`의 필수 관문을 통과한 주제를 선택한다.
4. **분석 완료**: 재현 가능한 코드·표·지도·민감도 분석을 만든다.
5. **보고서 작성**: 결과에서 확인된 범위만 정책 효과로 제시한다.

## 3인 팀의 첫 작업 분담

주제를 정하기 전에는 두 후보를 모두 조사하되, 각자 결과를 같은 형식으로 남긴다.

| 역할 | 먼저 맡을 일 | 남길 결과 |
|---|---|---|
| 자료 담당 | 두 후보의 원자료·라이선스·시간/공간 단위 확인 | `research/sources.csv`와 표본 데이터 설명 |
| 분석 담당 | 각 후보의 작은 표본 결합·핵심 산식 또는 경로 실험 | 재실행 가능한 코드와 표·그림 1개씩 |
| 정책·검증 담당 | 기존 정책, 대상자·수단 전환·배출 가정 검증 | 반례·제약·민감도 항목과 `docs/decision.md` 갱신 |

역할은 고정 전공이 아니라 첫 작업의 책임자다. 주제 선택은 세 사람이 표본 결과를 함께 검토한 뒤 기록한다.

## 작업 원칙

- `확인된 사실`, `가정`, `분석 결과`, `정책 시나리오`를 섞지 않는다.
- “35분 단축”, “25% 전환”, “연간 ○톤 감축” 같은 수치는 실제 계산·검증 전까지 목표나 예시로만 표시한다.
- 교통 격차나 탄소 감축의 인과효과를 관측 자료만으로 단정하지 않는다. 비교 기준과 가정을 함께 제시한다.
- 출처·라이선스·수집 시점·공간 및 시간 단위를 데이터별로 기록한다.
- 원본 데이터는 수정하지 않는다. 개인정보나 비공개 데이터는 이 폴더에 저장하지 않는다.
